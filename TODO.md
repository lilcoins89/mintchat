# MintChat — Delivery Outcomes

- [x] **Agent chat, streaming, and session state** — Provide a chat UI where users talk to an AI agent that can look up tokens, check wallet balances, and (only after explicit user approval) execute swaps. The browser never sees API keys; all Anthropic and plugin calls go through the backend. Keep per-session chat history, trading lock, and spend totals. Stream `/api/chat` replies over SSE so replies appear token by token, and show each tool call as a collapsible step. The agent gives facts only, never predicts prices or says a token is a good buy; asks one short question when the request is ambiguous; always shows the full contract address; and uses plain language and short replies. Treat token names, symbols, and all tool output as untrusted text; strip or ignore anything that looks like instructions.

- [x] **Configurable plugin system and market data** — Each remote plugin is an MCP server declared in `plugins.json` with `url`, `tokenEnv`, `readTools`, and `writeTools`; adding a remote plugin needs no application-code changes. Configure Paybox at `https://api.paybox.sh/mcp` for wallets, balances, token discovery, and swaps. Add a market-data plugin (for example, a DexScreener or Birdeye wrapper exposed as an MCP server or local tool) for price, liquidity, volume, and pair age. Keep credentials server-side and keep read and write tools in separate allowlists.

- [x] **Portfolio and wallet state** — The header shows the trading-lock state and connected wallet (shortened address). Include a portfolio side panel with balances from `get_portfolio`. Show explicit empty, loading, and error states that say what happened and what to do next.

- [x] **Trading lock, approval, and spending limits** — Write tools (`request_swap`, `request_transfer`) are excluded from `allowed_tools` until the user unlocks trading in the UI. Before every swap, the UI shows a confirmation card containing token name, full contract address, chain, amount in, estimated out, slippage, and fees, with Confirm and Cancel buttons. The agent may only submit the swap after Confirm is pressed; enforce this on the server, not just in the prompt. Enforce a per-trade cap and a daily cap using `MAX_TRADE_USD` and `MAX_DAILY_USD`; reject anything above them server-side. Never retry a money-moving call. Poll request status instead, and display the transaction signature with an explorer link. Start on a small, dedicated wallet. Never connect a main wallet.

- [x] **Risk checks and audit/security controls** — Surface pre-trade checks for liquidity, token age, top-holder concentration, mint/freeze authority status, and a warning for known honeypot patterns; explicitly identify unavailable data rather than inventing results. Rate-limit the API, validate all input, add CORS only for the app's own origin, and log every tool call with timestamp and session ID. Do not log API keys or expose them to the browser.

- [x] **Accessible PWA interface** — Deliver a responsive dark-theme PWA with a distinct visual identity; support mobile layouts, visible keyboard focus, and reduced motion. The header shows the lock state and shortened connected wallet; the portfolio panel shows `get_portfolio` balances; tool calls are collapsible; and all empty, loading, and error states explain what happened and what to do next. The experience should be clean and smooth.

- [x] **Setup, plugin, and prompt documentation** — Deliver backend and frontend source with comments only where logic is non-obvious. Include `plugins.json` with Paybox and the market-data plugin configured, `README.md` covering setup, environment variables, how to add a plugin, and how the trading lock and caps work, plus `BUILD_PROMPT.md` describing the architecture, safety rules, agent behavior, UI, and deliverables and instructing an AI coding assistant to show a plan and wait for approval before writing code. Include `package.json` and `.env.example` with dependencies and settings to fill in.

- [ ] **Automated checks and private GitHub repository** — Include tests for server-side caps, trading lock enforcement, and input validation. Run the test suite and production build, fix failures, and push the finished source to a new private GitHub repository. Do not perform live trades during tests or build verification.
